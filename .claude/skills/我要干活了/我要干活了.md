# 我要干活了！（状态机版）

---

## ⚠️ 第一步：强制检查 Superpower Skills

**在执行任何操作前，必须先运行检查：**

```bash
node .claude/skills/我要干活了/scripts/skill-checker.cjs
```

**检查结果处理：**
- ✅ 所有 skills 都在 → 可以继续
- ❌ 有 skills 缺失 → **流程立即阻断**，必须先安装完缺失的 skills

---

## 🚀 核心功能

1. 📋 **新增需求** — 分配编号 → 头脑风暴 → 规格设计 → 计划制定 → 分支隔离 → 任务执行 → 人工验证
2. 🔄 **执行需求** — 从已有需求继续执行，完整流程 + 七道门控
3. 📊 **查看项目状态** — 项目整体进度和需求状态

## 📍 状态定义

### 📍 状态：`INIT`

**入口点**

✅ 可以做：
1. 调用 `我要干活了/查看项目状态` 查看状态
2. 提示用户选择：新增需求 / 执行需求
3. 检查当前状态：`node .claude/skills/我要干活了/scripts/state-manager.cjs get`

❌ 不能做：
- 不能开始写代码
- 不能分配RQ编号
- 不能做任何需求实现

---

### 📍 状态：`NEED_RQ_NUMBER`

**必须先分配需求编号，没有任何例外！**

✅ **必须做**：
1. 询问用户需求信息：名称、描述、优先级、周期、是否豁免某些步骤
2. 分配需求编号：查看跟踪矩阵，分配下一个RQ编号，或运行脚本
   ```bash
   node .claude/skills/我要干活了/scripts/state-manager.cjs next-rq
   ```
3. 更新跟踪矩阵**三处**：
   - 需求表格新增一行
   - 需求总体统计更新（总数+1，待规划+1）
   - 执行时间线新增记录：`- 🆕 新增需求 {RQ-xxx}：{需求名称}`
4. **必须**：运行脚本生成HTML：
   ```bash
   node .claude/skills/我要干活了/scripts/markdown-to-html.cjs 项目执行跟踪矩阵.md
   ```
5. git commit：
   ```bash
   git add 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs(RQ-xxx): 新增需求"
   ```
6. 更新状态机：
   ```javascript
   // 使用脚本或手动编辑 state.json
   {
     "currentState": "NEED_BRAINSTORMING",
     "currentRQ": "RQ-xxx",
     "completedSteps": ["RQ编号分配"],
     "lastUpdated": "2026-05-20T15:00:00Z"
   }
   ```

❌ **不能做**：
- 不能跳过这步直接brainstorming
- 不能开始写代码

---

### 📍 状态：`NEED_BRAINSTORMING`

**必须调用 superpowers:brainstorming，没有任何例外！**

✅ **必须做**：
1. **调用 Skill** - `superpowers:brainstorming` 生成规格文档
2. 保存规格文档到 `docs/superpowers/specs/YYYY-MM-DD-{名称}-design.md`
3. **brainstorming完成后必须暂停，等待用户确认**
4. 用户确认后，更新跟踪矩阵三处：
   - 需求表格状态改为：📋规格已完成，填入规格文件链接
   - 需求总体统计：待规划-1，进行中+1
   - 执行时间线新增记录：`- 📋 生成规格：{RQ-xxx}`
5. git commit：
   ```bash
   git add docs/superpowers/specs/...
   git add 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs(RQ-xxx): 新增规格"
   ```
6. **必须**：运行脚本生成HTML
7. 更新状态机到 `NEED_PLAN`

❌ **不能做**：
- 不能直接写代码
- 不能跳过brainstorming

---

### 📍 状态：`NEED_PLAN`

**必须调用 superpowers:writing-plans，没有任何例外！**

✅ **必须做**：
1. **调用 Skill** - `superpowers:writing-plans` 生成执行计划
2. 保存计划文档到 `docs/superpowers/plans/YYYY-MM-DD-{名称}-implementation.md`
3. **AI 判断是否需要用户确认**：
   - **需要确认的情况**（暂停等待）：
     - 需求描述模糊或有歧义
     - 计划方案有多个可选
     - 计划涉及重大架构变更
     - 计划中的任务边界不清晰
     - 计划可能超出预期范围
   - **不需要确认的情况**（直接继续）：
     - 需求非常清晰明确
     - 计划方案简单直接、无歧义
     - 是常见的标准功能实现
     - 任务拆解清晰、边界明确
     - 和历史类似需求的执行模式一致
4. **如果需要确认**：等待用户确认后继续
5. **如果不需要确认**：直接继续，无需等待
6. 更新跟踪矩阵三处：
   - 需求表格状态改为：🔄计划已生成，填入计划文件链接
   - 需求总体统计：保持不变
   - 执行时间线新增记录：`- 📝 生成计划：{RQ-xxx}`（如果跳过确认，可备注：`- 📝 生成计划：{RQ-xxx} [AI判断无需确认]`）
7. git commit：
   ```bash
   git add docs/superpowers/plans/...
   git add 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs(RQ-xxx): 新增计划"
   ```
8. **必须**：运行脚本生成HTML
9. 更新状态机到 `NEED_BRANCH`

❌ **不能做**：
- 不能直接开始写代码
- 不能跳过writing-plans
- 不能在需要确认的情况下强行继续

---

### 📍 状态：`NEED_BRANCH`

**必须创建分支隔离开发！**

✅ **必须做**：
1. 检查当前分支：
   ```bash
   git branch --show-current
   ```
2. **如果在main分支上，创建feature分支**：
   ```bash
   git checkout -b feature/RQ-xxx
   ```
3. 更新跟踪矩阵三处：
   - 需求表格状态改为：🔄执行中
   - 执行时间线新增记录：`- 🌿 创建分支：{RQ-xxx}`
4. 生成HTML并commit
5. 更新状态机到 `EXECUTING_TASKS`

❌ **不能做**：
- 不能在main分支上直接写需求代码
- 不能跳过分支创建

**例外豁免**：如果用户明确说"在main上做"，可以跳过，但必须在跟踪矩阵备注中注明：`⚠️ 豁免分支隔离：{原因}`

---

### 📍 状态：`EXECUTING_TASKS`

**必须调用 superpowers:subagent-driven-development，没有任何例外！**

✅ **必须做**：
1. 读取计划文件，提取任务列表
2. 断点检测：检查git log，确定已完成任务数
   ```bash
   git log --oneline --grep="RQ-xxx"
   ```
3. **调用 Skill** - `superpowers:subagent-driven-development` 执行任务：
   - 注入上下文：识别到规格外新诉求 = BLOCKED
   - 注入上下文：commit message 格式 `feat(RQ-xxx/T{n}): {描述}`
   - 实现子代理串行派发
   - **强制两阶段审查！
4. 每个任务完成后：
   - 更新跟踪矩阵状态为 `🔄 N/M 任务完成`
   - 运行脚本生成HTML
5. 所有任务完成后，更新状态机到 `WAITING_VALIDATION`

❌ **不能做**：
- 不能跳过两阶段审查
- 不能并行执行任务
- 不能自己审查，必须派审查子代理
- 不能跳过 `superpowers:subagent-driven-development` 自己执行

---

### 📍 状态：`WAITING_VALIDATION`

**必须等用户明确说"ok"，没有任何例外！**

✅ **必须做**：
1. 启动dev server：
   ```bash
   npm run dev
   ```
2. 列出3-5个关键验证点给用户
3. **等待用户明确说"ok"**

❌ **不能做**：
- 不能直接标记完成
- 不能等TypeScript编译通过就算了
- 不能自己判断"看起来没问题"

**用户确认ok后必须做**：
1. 更新跟踪矩阵三处：
   - 需求表格状态改为：✅ 已完成
   - 需求总体统计：已完成+1，进行中-1
   - 执行时间线新增记录：`- ✅ 完成需求 {RQ-xxx}：{需求名称}`
2. 更新项目状态：最后更新日期更新
3. git commit：
   ```bash
   git add 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs(RQ-xxx): 完成需求"
   ```
4. 合并分支回main：
   ```bash
   git checkout main
   git merge feature/RQ-xxx
   git branch -d feature/RQ-xxx
   ```
5. 重置状态机到INIT：
   ```bash
   node .claude/skills/我要干活了/scripts/state-manager.cjs reset
   ```

---

### 📍 状态：`DONE`

**需求完成！**

可以回到INIT状态，等待下一个需求。

## 🔴 七道门控（状态机实现，绝对不可跳过）

| 门控 | 状态 | 内容 |
|------|------|------|
| 门控零 | NEED_BRAINSTORMING前 | 禁止直接动手，必须先走brainstorming |
| 门控零点五 | EXECUTING_TASKS中 | 识别到新需求→ BLOCKED，暂停提醒人类 |
| 门控零点六 | 所有状态 | 修改跟踪矩阵后必须运行脚本生成HTML |
| 门控一 | EXECUTING_TASKS每个任务 | 两阶段审查：规格合规+代码质量（含TDD检查） |
| 门控二 | NEED_PLAN | 子组件尺寸适配检查 |
| 门控三 | WAITING_VALIDATION | 人工验证，用户确认ok后才标记完成 |
| 门控四 | NEED_BRANCH | 分支隔离，不在main分支上直接开发 |

---

## 🛡️ 豁免机制

**人类在需求编号分配时，可以声明豁免特定步骤：**

| 豁免类型 | 适用场景 | 豁免后流程 |
|---------|---------|-----------|
| 跳过 brainstorming | 极简改动（改颜色、改文字） | 直接写计划 + 执行 |
| 跳过 writing-plans | 单一文件小修改 | brainstorming后直接执行 |
| 跳过分支隔离 | 紧急修复 | 在main上直接开发 |

**豁免规则**：
- 必须由人类明确声明，AI不得自行决定豁免
- 豁免必须在跟踪矩阵备注中记录
- 门控三（人工验证）永远不可豁免

位置：`.claude/skills/我要干活了/state.json`

格式：
```json
{
  "currentState": "NEED_BRAINSTORMING",
  "currentRQ": "RQ-037",
  "completedSteps": [
    "RQ编号分配"
  ],
  "lastUpdated": "2026-05-20T15:00:00Z"
}
```

**使用脚本管理状态**：
```bash
# 查看当前状态
node .claude/skills/我要干活了/scripts/state-manager.cjs get

# 重置到INIT

```
