# 新增需求 📋 (状态机版)

---

## ⚠️ 第一步：强制检查 Superpower Skills

**在执行任何操作前，必须先运行检查：**

```bash
node .claude/skills/我要干活了/scripts/skill-checker.cjs
```

**检查结果处理：**
- ✅ 所有 skills 都在 → 可以继续
- ❌ 有 skills 缺失 → **流程立即阻断**，必须先安装完缺失的 skills 才能继续

---

## 🔴 铁律（强制遵守）

1. **必须先分配RQ编号** - 没有例外
2. **必须更新跟踪矩阵三处** - 表格+统计+时间线
3. **必须生成HTML** - 修改跟踪矩阵后立即运行脚本
4. **必须Git Commit** - 每个步骤完成后提交

---

## 📍 当前状态检查

在开始前，先确认当前状态：
```bash
node .claude/skills/我要干活了/scripts/state-manager.cjs get
```

**必须在 `INIT` 或 `NEED_RQ_NUMBER` 状态才能开始**

## 🎯 完整流程（状态机驱动）

### 阶段1：收集需求信息 & 分配RQ编号

**目标状态**：`NEED_RQ_NUMBER` → `NEED_BRAINSTORMING`

**步骤**：
1. 询问用户以下信息：
   - 需求名称（必填）
   - 需求描述（可选，默认=名称）
   - 优先级（可选，默认=高）
   - 预计周期（可选，默认=1天）
   - 是否有豁免（可选）

2. 获取下一个RQ编号：
   ```bash
   node .claude/skills/我要干活了/scripts/state-manager.cjs next-rq
   ```

3. 更新跟踪矩阵（三处）：
   - **需求表格** - 新增一行
   - **需求统计** - 总数+1，待规划+1
   - **执行时间线** - 追加 `- 🆕 新增需求 {RQ}：{名称}`

4. 生成HTML：
   ```bash
   node .claude/skills/我要干活了/scripts/markdown-to-html.cjs 项目执行跟踪矩阵.md
   ```

5. Git Commit：
   ```bash
   git add 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs({RQ}): 新增需求"
   ```

6. 更新状态：
   ```javascript
   StateManager.transitionTo('NEED_BRAINSTORMING', {
       currentRQ: 'RQ-xxx',
       addStep: 'RQ编号分配'
   });
   ```

---

### 阶段2：Brainstorming 生成规格

**目标状态**：`NEED_BRAINSTORMING` → `NEED_PLAN`

**步骤**：
1. 明确告诉用户："现在开始Brainstorming生成规格文档，完成后需要你手动接管"

2. 进行需求分析和规格设计，生成文档到 `docs/superpowers/specs/`

3. Brainstorming完成后，**暂停并等待用户确认**

4. 用户确认后，更新跟踪矩阵（三处）：
   - **需求表格** - 状态改为 `📋 规格已完成`，填入规格文件链接
   - **需求统计** - 待规划-1，进行中+1
   - **执行时间线** - 追加 `- 📋 生成规格：{RQ}`

5. 生成HTML：
   ```bash
   node .claude/skills/我要干活了/scripts/markdown-to-html.cjs 项目执行跟踪矩阵.md
   ```

6. Git Commit：
   ```bash
   git add docs/superpowers/specs/{文件} 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs({RQ}): 新增规格"
   ```

7. 更新状态：
   ```javascript
   StateManager.transitionTo('NEED_PLAN', {
       addStep: '规格设计完成'
   });
   ```

---

### 阶段3：Writing-Plans 生成计划

**目标状态**：`NEED_PLAN` → `NEED_BRANCH`

**步骤**：
1. 明确告诉用户："现在开始生成实现计划"

2. 调用 `superpowers:writing-plans` 生成实现计划到 `docs/superpowers/plans/`

3. Writing-Plans完成后，**AI 判断是否需要用户确认**：
   - **需要确认的情况**（暂停等待）：
     - 需求描述模糊或有歧义
     - 计划方案有多个可选
     - 计划涉及重大架构变更
     - 计划中的任务边界不清晰
     - 计划可能超出预期范围
   - **不需要确认的情况**（直接继续）：
     - 需求非常清晰明确
     - 计划方案简单直接、无歧义
     - 是常见的标准功能实现
     - 任务拆解清晰、边界明确
     - 和历史类似需求的执行模式一致

4. **如果需要确认**：等待用户确认后继续

5. **如果不需要确认**：直接继续，无需等待

6. 更新跟踪矩阵（三处）：
   - **需求表格** - 状态改为 `🔄 计划已生成`，填入计划文件链接
   - **需求统计** - 保持不变
   - **执行时间线** - 追加 `- 📝 生成计划：{RQ}`（如果跳过确认，可备注：`- 📝 生成计划：{RQ} [AI判断无需确认]`）

7. 生成HTML：
   ```bash
   node .claude/skills/我要干活了/scripts/markdown-to-html.cjs 项目执行跟踪矩阵.md
   ```

8. Git Commit：
   ```bash
   git add docs/superpowers/plans/{文件} 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs({RQ}): 新增计划"
   ```

9. 更新状态：
   ```javascript
   StateManager.transitionTo('NEED_BRANCH', {
       addStep: '计划制定完成'
   });
   ```

---

### 阶段4：创建分支隔离

**目标状态**：`NEED_BRANCH` → `EXECUTING_TASKS`

**步骤**：
1. 检查当前分支：
   ```bash
   git branch --show-current
   ```

2. 如果在main分支，创建feature分支：
   ```bash
   git checkout -b feature/{RQ}
   ```

3. 更新跟踪矩阵（三处）：
   - **需求表格** - 状态改为 `🔄 执行中`
   - **需求统计** - 保持不变
   - **执行时间线** - 追加 `- 🌿 创建分支：{RQ}`

4. 生成HTML：
   ```bash
   node .claude/skills/我要干活了/scripts/markdown-to-html.cjs 项目执行跟踪矩阵.md
   ```

5. Git Commit（如果有变更）：
   ```bash
   git add 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs({RQ}): 创建分支"
   ```

6. 更新状态：
   ```javascript
   StateManager.transitionTo('EXECUTING_TASKS', {
       addStep: '分支创建完成'
   });
   ```

---

### 阶段5：执行任务

**目标状态**：`EXECUTING_TASKS` → `WAITING_VALIDATION`

**步骤**：
1. 读取计划文档，提取任务列表

2. 逐个执行任务，**每个任务完成后**：
   - 更新跟踪矩阵：`🔄 {n}/{m} 任务完成`
   - 生成HTML
   - Git Commit：`feat({RQ}/T{n}): {描述}`

3. 所有任务完成后，更新跟踪矩阵（三处）：
   - **需求表格** - 状态改为 `⏳ 等待验证`
   - **需求统计** - 保持不变
   - **执行时间线** - 追加 `- ✅ 任务全部完成：{RQ}`

4. 生成HTML

5. 更新状态：
   ```javascript
   StateManager.transitionTo('WAITING_VALIDATION', {
       addStep: '任务执行完成'
   });
   ```

---

### 阶段6：人工验证

**目标状态**：`WAITING_VALIDATION` → `DONE`

**步骤**：
1. 启动Dev Server：
   ```bash
   npm run dev
   ```

2. 列出3-5个关键验证点给用户

3. **等待用户明确说"ok"**（不能自己判断）

4. 用户确认后，更新跟踪矩阵（三处）：
   - **需求表格** - 状态改为 `✅ 已完成`
   - **需求统计** - 已完成+1，进行中-1
   - **执行时间线** - 追加 `- ✅ 完成需求 {RQ}：{名称}`
   - **项目状态** - 更新最后更新日期

5. 生成HTML

6. Git Commit：
   ```bash
   git add 项目执行跟踪矩阵.md 项目执行跟踪矩阵.html
   git commit -m "docs({RQ}): 完成需求"
   ```

7. 合并分支回main：
   ```bash
   git checkout main
   git merge feature/{RQ}
   git branch -d feature/{RQ}
   ```

8. 更新状态：
   ```javascript
   StateManager.transitionTo('DONE', {
       addStep: '需求完成'
   });
   ```

---

### 阶段7：回到INIT

**目标状态**：`DONE` → `INIT`

```javascript
StateManager.resetToInit();
```

## 📊 状态转换速查表

| 当前状态 | 可以转到 | 触发动作 |
|---------|---------|---------|
| INIT | NEED_RQ_NUMBER | 用户选择新增需求 |
| NEED_RQ_NUMBER | NEED_BRAINSTORMING | RQ分配完成 |
| NEED_BRAINSTORMING | NEED_PLAN | 规格生成完成 |
| NEED_PLAN | NEED_BRANCH | 计划生成完成 |
| NEED_BRANCH | EXECUTING_TASKS | 分支创建完成 |
| EXECUTING_TASKS | WAITING_VALIDATION | 任务全部完成 |
| WAITING_VALIDATION | DONE | 用户验证通过 |
| DONE | INIT | 清理状态 |

---

## ⚠️ 注意事项

1. **每个状态转换必须更新 `state.json`**
2. **每次修改跟踪矩阵必须生成HTML**
3. **每个步骤完成后必须Git Commit**
4. **Brainstorming和Writing-Plans完成后必须暂停等待用户确认**
5. **WAITING_VALIDATION状态必须等用户说"ok"才能继续**
