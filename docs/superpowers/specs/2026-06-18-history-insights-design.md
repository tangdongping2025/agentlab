# 历史洞察

## 背景

历史会话除了用于恢复上下文，还可以作为用户长期使用习惯和近期关注主题的原始语料。当前阶段先做只读分析，不自动写入长期记忆，也不自动进入知识库，避免把一次偶然对话误判为稳定偏好或可靠知识素材。

## 需求

1. 在历史功能中提供“历史洞察”视角，从已有 agent session 中提炼候选洞察。
2. 候选洞察分为两类：
   - 使用习惯：用户的协作偏好、决策倾向、界面偏好、验收习惯等。
   - 关注主题：用户近期反复讨论或正在推进的 topic，以及可作为后续知识库素材的主题。
3. 每条候选洞察必须能追溯到相关 session，方便用户判断是否误判。
4. 第一版只展示候选结论，不提供自动采纳、自动写入记忆或自动写入知识库。

## 设计

- 在历史页现有“历史与恢复”能力旁增加只读的“历史洞察”区域或视图。
- 数据来源复用现有 session 查询能力：先拉取最近一批 agent session，再按需读取 session detail 中的消息内容。
- 洞察生成第一版采用前端确定性启发式，不调用 LLM：
  - 关注主题：从 session 名称、preview、用户消息中提取高频中文/英文关键词，过滤短词和常见停用词，按出现 session 数排序。
  - 使用习惯：基于可解释规则生成候选项，例如频繁出现“先设计/规格/计划/验证/不要/去掉/隐藏/恢复”等表达时，形成对应候选习惯。
- 每条洞察展示：标题、简短说明、证据 session 列表。
- 点击证据 session 可复用现有详情加载与恢复能力。

## 不做

- 不新增 Task / Task Segment 模型。
- 不新增知识库表。
- 不写入 Claude Code memory 或项目长期偏好。
- 不自动生成系统提示词。
- 不调用 LLM 做总结。
- 不分析非 agent session，除非用户后续明确需要。

## 验收

- 用户可以在历史功能中看到“历史洞察”入口或区域。
- 页面展示“使用习惯候选”和“关注主题候选”。
- 每条候选洞察都能看到来源 session。
- 点击来源 session 后仍能查看原会话详情，并可继续上下文。
- 关闭或切回历史恢复视图时，不影响现有查询、详情和恢复功能。
