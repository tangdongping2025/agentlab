# 任务列表发送后刷新稳定性修复

## 背景

对话窗口任务列表由 `workspaceMessages` 与 `workspaceTaskIndex` 派生；用户发送新消息时，前端会先追加一条尚未持久化、没有 `seq` 的 user 消息，任务列表应立即增加一条。

## 问题

未持久化消息使用 `m.seq ?? i` 作为 React key 时，可能与已有持久化消息的数字 `seq` 冲突，React 会提示重复 key，并可能导致消息/任务相关 UI 更新不稳定。

## 目标

发送新用户消息后，任务列表应稳定、立即增加新任务；消息渲染 key 不得在持久化 `seq` 与本地数组下标之间冲突。

## 方案

仅调整消息列表渲染 key：有 `seq` 的消息使用带命名空间的持久化 key，无 `seq` 的本地临时消息使用带命名空间的本地 key。任务派生规则、后端 message-index、分页逻辑保持不变。

## 验收

新增回归测试覆盖已有 `seq` 消息后发送新消息的场景，确认任务计数更新且不再触发重复 key 警告。
