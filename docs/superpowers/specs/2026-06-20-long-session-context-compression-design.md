# 长会话上下文压缩设计

## 背景

Agent workspace 当前会把完整会话历史发送给后端，后端再把历史拼进 Claude SDK 的 prompt。一次会话内容越多，每次运行的输入越长，模型响应会变慢，也更容易触发 nginx SSE upstream read timeout，导致前端出现 `Load failed` 一类网络层失败。

本需求的目标是让长会话继续可用：保留完整历史记录，同时为 Agent 运行生成更短的上下文视图。

## 目标

- 自动控制发送给 Agent 的上下文长度，降低长会话变慢和超时概率。
- 原始会话消息完整保存在 MySQL，不因压缩被删除、覆盖或改写。
- 压缩过程尽量无感，只在必要时给用户轻提示。
- 支持增量压缩，避免每次都从头处理全部历史。

## 非目标

- 不做完整 RAG 检索系统。
- 不做多版本摘要编辑器。
- 不引入复杂 tokenizer 依赖，第一版使用字符数近似判断。
- 不改变历史页展示的完整会话内容。

## 默认策略

### 阈值

- 软阈值：运行时上下文约 40,000 字符。
- 硬阈值：运行时上下文约 80,000 字符。
- 保留窗口：默认最近 8 轮用户-助手对话完整保留。
- 极端降级：压缩后仍超过硬阈值时，完整窗口降为最近 4 轮。

### 再次压缩条件

满足任一条件时触发增量压缩：

1. 摘要 + 最近完整窗口 + 当前请求超过 40,000 字符。
2. 距离上次摘要点之后新增超过 12 轮对话。
3. 距离上次摘要点之后新增内容超过 20,000 字符。

## 数据保留原则

原始 `messages` 是真相源，必须完整保留。

压缩只生成运行时派生数据，例如：

- `contextSummary`：早期会话摘要。
- `summaryUntilMessageIndex`：摘要覆盖到的消息序号。
- `summaryUpdatedAt`：摘要更新时间。

这些派生数据不得替代原始消息。用户历史页、导出、复盘、洞察和后续 RAG 仍读取完整原始消息。

## 运行时上下文组装

发送给 Agent 的 prompt 由后端组装，不再直接拼接全部历史。

当未超过阈值时：

```text
以下是之前的对话历史：
<完整历史>

请回答当前最新请求：
用户: <当前请求>
```

当超过阈值时：

```text
以下是早期对话摘要：
<contextSummary>

以下是最近 8 轮完整对话：
<recentMessages>

请回答当前最新请求：
用户: <当前请求>
```

硬阈值降级时，最近完整对话窗口改为 4 轮。

## 增量压缩流程

1. 后端接收 Agent run 请求。
2. 根据当前消息计算运行时上下文长度。
3. 如果未超过阈值，直接组装完整历史 prompt。
4. 如果超过阈值，读取已有 `contextSummary` 和 `summaryUntilMessageIndex`。
5. 将“旧摘要 + 上次摘要点之后、但不属于最近完整窗口的消息”压缩为新摘要。
6. 保存新摘要元数据，但不改写原始消息。
7. 用“新摘要 + 最近完整窗口 + 当前请求”运行 Agent。

## 用户提示

正常自动压缩时不弹窗打断。

满足以下情况时，在对话区显示轻提示：

- 本次运行使用了压缩上下文。
- 连续 3 次运行都触发压缩。
- 压缩后仍接近硬阈值。

提示文案建议：

```text
当前会话较长，已自动压缩早期上下文以保持响应速度。原始会话记录仍完整保留。
```

如果压缩后仍很长：

```text
当前会话非常长，已保留最近关键上下文。若回答变慢，建议开启新会话。
```

## 错误处理

- 摘要生成失败时，不修改摘要元数据，不修改原始消息。
- 摘要失败后本次运行可退回“最近 8 轮完整对话 + 当前请求”的安全模式，并提示上下文可能不完整。
- Agent 正常执行失败仍按现有错误通路显示。

## SSE 超时配套

本需求重点是减少长上下文导致的慢响应，但还应配套调整 nginx Agent SSE 反代超时：

- `/api/agents` location 增加较长 `proxy_read_timeout`。
- 保持 `proxy_buffering off`。

该调整不能替代上下文压缩，只是避免合理长任务被过早切断。

## 测试要求

- 后端测试：未超过阈值时使用完整历史。
- 后端测试：超过软阈值时生成摘要上下文，并保留最近 8 轮完整对话。
- 后端测试：压缩后仍超过硬阈值时降为最近 4 轮。
- 后端测试：原始 messages 不被摘要覆盖。
- 前端测试：压缩提示可渲染且不打断对话。
- nginx 配置检查：`/api/agents` 保持 SSE buffering off，并设置较长 read timeout。

## 验收标准

- 长会话运行时，Agent 入参不再包含无界增长的完整历史。
- MySQL 中原始消息数量和内容不因压缩减少或变化。
- 用户能在历史页看到完整原始会话。
- 触发压缩时用户能看到轻提示，知道原始记录仍保留。
- Docker 版本中长会话不再容易因 nginx 默认读超时出现 `Load failed`。
