# 历史洞察显式触发

## 背景

当前“历史洞察”入口表现为 tab 切换，但切换后会立即分析历史会话。用户感知上这更像进入视图，而不是主动触发分析，和“候选洞察必须由用户确认”的产品边界不一致。

## 需求

1. 点击“历史洞察”只进入洞察视图，不自动分析历史会话。
2. 洞察视图提供明确的“分析历史会话”按钮，由用户点击后才生成候选洞察。
3. 已生成结果保留在当前页面状态中，用户可点击“重新分析”刷新候选。
4. 保持已有采纳、忽略、来源 session 追溯能力不变。

## 不做

- 不新增后台自动分析任务。
- 不自动采纳或启用习惯。
- 不调用 LLM 做总结。
- 不改变沉淀库和 prompt 生效逻辑。

## 验收

- 切到“历史洞察”后，未点击按钮前不展示候选列表。
- 点击“分析历史会话”后展示“使用习惯候选”和“关注主题候选”。
- 结果存在时按钮文案变为“重新分析”。
- 既有采纳、忽略和来源 session 打开行为不回归。
