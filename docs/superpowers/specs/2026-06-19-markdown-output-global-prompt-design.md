# Markdown 输出规范全局提示词设计

## 背景

AI 回复 Markdown 文章卡样式已经实现，但模型如果输出大段普通文本，文章卡的结构化阅读优势仍然无法稳定体现。用户提供了通用正文、对比分析、项目/方案说明、问题排查四类 Markdown 模板，希望沉淀为系统提示词。

## 目标

把模板合集转化为一段全局系统提示词中的 Markdown 输出规范，让支持全局提示词的智能体在复杂回答中优先输出结构清晰的 Markdown。

## 范围

- 通过现有全局提示词设置写入 `[Markdown 输出规范]` 段落。
- 适用智能体沿用现有全局提示词机制：`assistant`、`research`、`claude-sdk`。
- 保留已有全局提示词内容，不整体覆盖。
- 若已有 `[Markdown 输出规范]` 段落，则替换该段落；否则追加到末尾。
- 简单问答不强制套模板，避免机械化回复。

## 提示词内容

```md
[Markdown 输出规范]

当回答复杂问题、分析问题、给方案、做对比、写项目说明或排查步骤时，优先使用清晰的 Markdown 结构，让内容适合文章卡阅读。

通用正文优先结构：
## 核心判断
先用一句话给出结论。

---
## 1. 要点一
展开说明，并在适合时使用列表：
- 子点一
- 子点二
- 子点三

## 2. 要点二
可以在关键提醒处使用引用块：
> 引用说明或关键提示。

## 3. 要点三
适合对齐信息时使用表格：
| 维度 | 说明 |
|---|---|
| 条目A | 内容 |
| 条目B | 内容 |

---
## 总结
给出收尾结论或下一步建议。

任务类型选择：
- 对比分析：优先使用表格列出维度、方案A、方案B，并给出“选型建议”和理由。
- 项目/方案说明：优先使用“总体概览 / 详细内容 / 承诺与保障”结构。
- 问题排查或步骤指导：优先使用“问题现象 / 可能原因 / 解决步骤”结构。
- 简单问答、确认类回复、闲聊回复：不要强行套模板，保持简洁自然。

输出要求：
- 标题层级清晰，优先使用 `##` 和 `###`。
- 长段落拆成短段落。
- 能用列表表达步骤或要点时优先用列表。
- 能用表格提升对比清晰度时优先用表格。
- 代码、命令和文件路径使用 Markdown 代码格式。
- 不要为了套模板而添加无意义章节。
[/Markdown 输出规范]
```

## 验收

- 全局提示词设置保持启用。
- 当前全局提示词包含且只包含一个 `[Markdown 输出规范]` 段落。
- 现有全局提示词原内容保留。
- 新对话中复杂问题更倾向输出标题、列表、表格、引用等 Markdown 结构。
