# 智能体对话窗口全屏化设计

## 背景

Agent Runtime 的主对话区目前固定嵌在页面布局中。用户在查看长对话或持续与智能体交互时，希望临时放大主对话区，减少侧栏和其他工作区干扰。

## 目标

给智能体主对话区增加全屏化能力：

- 作用范围：主对话区。
- 入口：对话头部按钮。
- 全屏内容：消息列表和输入框都保留，可继续发送消息或停止运行。
- 退出方式：头部按钮退出、Esc 退出、点击遮罩外层退出。

## 范围

- 修改 `ChatWorkspace`。
- 全屏状态仅为前端本地 UI 状态，不持久化。
- 全屏时继续使用同一份 Zustand workspace 状态。
- 全屏时复用现有消息渲染、流式内容、事件展示、输入框、发送/停止逻辑。

## 非目标

- 不改变智能体运行逻辑。
- 不改变会话存储。
- 不全屏整个智能体页面。
- 不全屏右侧文件区或 Tabs 工作区。
- 不新增快捷键发送行为。

## 交互

常规模式：

- 对话头部右侧显示“全屏”按钮，与“新对话”按钮并列。
- 点击“全屏”后打开固定定位的 overlay。

全屏模式：

- overlay 覆盖视口，内部保留对话头部、消息列表、输入区。
- 头部按钮显示“退出全屏”。
- Esc 关闭 overlay。
- 点击 overlay 背景关闭 overlay，点击对话面板内部不关闭。

## 布局约束

- overlay 使用 `position: fixed; inset: 0; z-index` 高于普通页面。
- 面板 `margin: 24px`，高度通过 flex 占满剩余空间。
- 消息列表 `flex: 1; overflow-y: auto`，输入区 `flex-shrink: 0`，确保输入框不会被消息列表挤出视口。
- 常规模式保持原尺寸和原布局。

## 验证

- 单元测试覆盖：点击“全屏”后出现“退出全屏”；输入框仍存在；按 Esc 后退出。
- TypeScript 检查通过。
- 构建通过。
- 浏览器手动验证常规发送、全屏发送、Esc/按钮/遮罩退出。
