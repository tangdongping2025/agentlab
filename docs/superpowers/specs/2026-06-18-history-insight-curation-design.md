# 历史洞察沉淀闭环

## 背景

历史洞察已经能从 agent session 中只读提炼“使用习惯候选”和“关注主题候选”。下一步需要把这些候选变成可人工确认的长期资产：一部分沉淀为用户协作习惯，一部分沉淀为后续知识库素材。

## 需求

1. 在“历史洞察”候选项上提供人工处理动作：
   - 采纳为习惯
   - 采纳为知识素材
   - 忽略
2. 增加“沉淀库”视角，展示已采纳的两类内容：
   - 用户习惯库：协作偏好、界面偏好、验证习惯、工作方式等。
   - 知识素材池：近期关注 topic、项目背景、后续可整理进知识库的素材。
3. 每条沉淀内容必须保留来源 session，用户可以回到原 session 查看上下文。
4. 沉淀内容必须持久化，刷新页面后仍可查看。
5. 用户可以撤销或删除已采纳内容。
6. 忽略的候选不再在当前洞察列表中反复干扰用户。

## 设计

- 数据流：历史会话 → 洞察候选 → 用户采纳/忽略 → 沉淀库。
- 第一版使用后端持久化表保存沉淀结果，避免长期资产只存在浏览器本地。
- 新增后端模型建议为 `insight_items`：
  - `id`
  - `kind`: `habit | knowledge`
  - `title`
  - `description`
  - `source_session_ids`
  - `status`: `accepted | ignored`
  - `created_at`
  - `updated_at`
- 前端在 HistoryPage 现有“历史洞察”模式中扩展：
  - 候选卡片显示采纳/忽略动作。
  - 新增“沉淀库”入口或子视图，按习惯和知识素材两栏展示。
  - 来源 session 按钮复用现有详情打开逻辑。
- 后端提供最小 CRUD：
  - 查询沉淀项。
  - 创建采纳项或忽略项。
  - 删除或撤销沉淀项。
- 候选生成仍沿用当前前端确定性启发式；本需求只处理人工确认和持久化闭环。

## 不做

- 不自动写入 Claude Code memory。
- 不自动修改系统提示词。
- 不自动进入 RAG 检索。
- 不新增完整知识库表、embedding 或向量检索。
- 不调用 LLM 总结或改写候选内容。
- 不引入 Task / Task Segment 模型。

## 验收

- 用户可以在历史洞察候选上执行“采纳为习惯”“采纳为知识素材”“忽略”。
- 已采纳内容出现在沉淀库，并按习惯/知识素材区分。
- 页面刷新后沉淀内容仍存在。
- 每条沉淀内容能打开来源 session。
- 删除或撤销后，该内容不再显示为已采纳。
- 当前历史与恢复、session 详情、继续上下文能力不回归。
